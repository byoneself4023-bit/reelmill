# 대본

**기본은 사용자가 주제를 직접 적는 것이다.** 주제가 없으면 0-1에서 제목을 제안한다.

**채널 설정을 먼저 읽는다.** `reelmill/channel.md`(말투 · 안 쓰는 말 · 하지 않을 주장 · 채널 관점). **말투·낱말·관점은 이 파일이, 사실·구조(팩트체크·5부 구조·시점·사실 규칙)는 이 스킬이 정한다** — 둘이 부딪히면 그 기준대로. 파일이 없으면 시작 전에 다섯 가지(채널 한 줄 · 보는 사람 · 말투 · 안 쓰는 말 · 하지 않을 주장)를 묻고 `channel.example.md` 모양으로 만든다. 자가 검토 ⑦의 「채널 관점」은 이 파일의 관점을 대본에 한 줄 이상 살리는 것이다.

단계마다 **멈추고 사용자의 선택을 기다린다.** 한 번에 여러 단계를 진행하지 않는다.

## 0. 주제 정하기

### 0-1 주제가 없을 때만 — 제목 15개

- 분야를 한 줄로 묻는다(예: 부동산, 건강, 경제). 분야도 없으면 아래 니치 중 고르게 한다:
  돈과 권력 · 기술과 AI · 역사의 전환점 · 기업 비화 · 재난과 인프라 · 에너지와 기후 · 식량과 물류 · 노동과 고용 · 의료와 제약 · 생활 속 과학
- 분야 안에서 **제목만 15개**를 번호로 낸다. 설명은 붙이지 않는다(훑어보기 쉬워야 한다).
  - 궁금하게 쓴다. 「층간소음 규정」 ❌ → 「아파트 2층이 1층보다 시끄러운 이유」 ⭕
  - **눈에 보이는 대상 + 의외의 원리**가 있는 제목을 우선한다(구조·물건·장소·몸·돈의 흐름). 규정 나열만 있는 제목은 빼거나 대상을 붙인다.
  - 15개가 서로 다른 각도여야 한다. 마지막에 "번호로 고르거나 다른 주제를 직접 말해 주세요".
- 검색하지 않는다. 할당량·시간을 쓰지 않는다.
- **겹침 피하기 (대화가 바뀌어도 유지)** — 기록은 `work/ideas/history.jsonl`, 다루는 건 `scripts/ideas.py`. 기록 전체를 직접 읽지 않는다.
  1. 후보를 20개쯤 떠올린 뒤 겹침부터 확인한다:
     `uv run .claude/skills/shorts-script/scripts/ideas.py check "후보1" "후보2" …`
     「겹침」으로 나온 후보는 빼고 15개를 채운다(니치와 상관없이 같은 질문이면 겹침).
     스크립트는 같은 낱말만 잡는다. 「골프공 딤플」과 「골프공 표면의 구멍」처럼 말만 다른 같은 질문은 내가 한 번 더 보고 뺀다.
  2. 낸 15개를 기록한다: `uv run …/ideas.py add --niche "<니치>" "제목1" …`
  3. 사용자가 고르면 표시한다: `uv run …/ideas.py pick "<제목>"` (4절에서 저장 폴더가 생기면 `--episode` 로 연결)
  - 추천만 하고 고르지 않은 제목은 **180일이 지나면 다시 추천될 수 있다.** 시간이 지나면 보는 눈이 달라질 수 있어서다. 고른 제목은 계속 막는다.
  - "다른 주제 15개 더"라고 하면 같은 순서로 새 15개를 낸다.
  - 한 니치에서 새 각도가 잘 안 나오면 더 좁은 니치(예: 스포츠 → 스포츠 과학·스포츠 경제학)를 제안한다.
- **추천 3개** — 15개 아래에 ⭐ 3개를 골라 이유를 한 줄씩 붙인다. 기준:
  - 3조건 가능성(공식 자료로 확인될 사실, 반론, 1분에 담길 만큼 좁음)
  - 눈에 보이는 대상 + 의외의 원리
  - 코드로 그릴 장면이 분명한가
  - 3개가 서로 다른 유형·이야기 틀(예: 원리형·이야기형·숫자형). 숫자형만 고르지 않는다
  - 유래가 여러 설뿐이라 확인할 사실이 약한 주제는 추천에서 뺀다
- **분야가 아니라 주제를 바로 적었으면** 15개를 건너뛰고 0-2로 간다(이때도 `pick` 으로 기록한다). 입력이 애매하게 넓으면 0-2를 해 보고 좁히는 대안을 보여 준다.

### 0-2 주제를 받으면 — 3조건 검증

주제가 문장으로 와도 된다. 한 문장 질문으로 다듬은 뒤 세 조건을 본다.

| 조건 | 판단 |
|---|---|
| **확인할 사실이 있는가** | 출처로 확인되는 사실(숫자·연도·인물·사건·원리·실제 사례)이 1분에 3~5개 나오는가. 숫자가 없어도 된다 |
| **반론이 있는가** | "그럼 ~하면 되지 않나?", "그게 정말 손해인가?" 같은 반대편이 있는가 — 4부(복잡화)의 재료 |
| **충분히 좁은가** | 고른 길이에 질문 하나로 담기는가. 「AI와 일자리」 ❌ → 「AI 때문에 초급 개발자 채용이 줄었나」 ⭕ |

- 하나라도 안 되면 솔직히 말하고 좁히는 대안 2~3개를 준다.
- 전제 확인은 **한 줄만**. 명백히 틀린 전제일 때만 멈춘다. 여기서 조사하지 않는다.
- 통과하면 **유형과 이야기 틀**을 하나 고르고 한 줄로 밝힌다(아래 2절).

### 0-3 길이 묻기

"이 영상은 얼마나 길게 만들까요?" — 번호로 고르게 한다. 글자 수는 공백 포함 어림값이다. 일레븐랩스 기본 설정(eleven_v4 · 속도 1.0) 실측으로 약 520자가 65~67초였다(금메달·로또·1호선). 숫자는 소리로 읽으면 글자가 늘어난다(「529」→「오백이십구」) — 정확한 길이는 2단계 나레이션을 만들면 나온다.

| # | 길이 | 나레이션 | 문장 |
|---|---|---|---|
| 1 | 30초 | 약 265자 | 8~10개 |
| 2 | 1분 | 약 530자 | 16~20개 |
| 3 | 90초 | 약 800자 | 24~30개 |
| 4 | 2분 | 약 1,060자 | 32~40개 |
| 5 | 3분 | 약 1,600자 | 48~60개 |

- 처음이면 1분을 권한다. 목소리를 바꾸면 2단계 나레이션 실측으로 이 표를 다시 맞춘다.
- 주제와 길이가 둘 다 정해질 때까지 1절로 넘어가지 않는다.

## 1. 대본 먼저, 팩트체크는 그다음 — 한 답변에 함께

### 1-1 대본 쓰기 (이 답변의 본체)

**5부 구조** (모든 유형 공통)

| 부 | 분량 | 내용 |
|---|---|---|
| 1. 콜드 오픈 | 처음 2~4문장 | 설명 없이 바로. 구체적 대상 + 모순·극단적 숫자·의외의 장면·질문 중 하나. 배경 설명 금지 |
| 2. 전환 | 1~2문장 | 줌아웃 신호. "이걸 이해하려면", "그런데 여기서 끝이 아닙니다" |
| 3. 상승 설명 | **50~70%** | 단계별 전개. 숫자·크기 비교·원리·사건의 순서 같은 구체적 디테일 |
| 4. 복잡화 | 2~4문장 | 긴장·대가·아이러니. 0-2에서 찾은 반론을 쓴다 |
| 5. 되받는 마무리 | 마지막 1~2문장 | 콜드 오픈으로 돌아가되 의미가 달라져 있다. 마지막 문장은 기억에 남게 |

**콜드 오픈 공식** — 첫 문장은 아래 공식 중 **서로 다른 2~3개로 써 보고** 하나를 고른다. 고른 공식 이름을 script.md 머리말 「콜드 오픈:」 줄에 적는다. 얼굴 없는 한국어 쇼츠에 맞는 12개만 골랐다(youtube-agent-skill hooks.json, MIT, Jake Schincariol — 「내가 해 봤다」「화면 녹화」「캡처 증거」처럼 얼굴·녹화가 필요한 공식은 뺐다).

| 공식 | 모양 | 예 | 실패하는 때 |
|---|---|---|---|
| 통계 | 몰랐던 숫자를 담담하게 → 그 결과 | 아파트 한 가구에 294만 명이 몰렸습니다 | 숫자가 흐릿하거나 출처가 없을 때 |
| 실수 지적 | 시청자가 지금 하고 있을 실수 | 전세 계약서, 이 칸부터 보시면 늦습니다 | 흔한 실수가 아니거나 바로 확인이 안 될 때 |
| 통념 뒤집기 | 다들 맞다는 말 → 아니다 | 남향이 무조건 좋다는 말, 반은 틀렸습니다 | 바로 뒤에 근거가 안 나올 때 |
| 최상급 | 가장 ~한 것 하나 | 서울에서 가장 비싼 주차장은 아파트 안에 있습니다 | 무엇을 이겼는지 안 밝힐 때 |
| 질문 | 시청자가 검색창에 칠 질문 그대로 | 금메달은 왜 금이 아닐까요 | 내 질문이지 시청자 질문이 아닐 때 |
| 전후 비교 | 두 상태, 그 사이 한 번의 변화 | 2017년 4억, 2024년 14억 | 눈에 보이는 변화가 없을 때 |
| 목록 | 개수를 첫 줄에 | 청약 가점이 깎이는 세 가지 | 개수가 틀리거나 항목이 겹칠 때 |
| 아는 사람만 아는 것 | 제도·시스템 안쪽 정보 | 분양가는 시장이 아니라 계산으로 정해집니다 | 없는 내부 정보를 아는 척할 때 |
| 말이 안 되는 주장 | 틀려 보이는 말 → 바로 증명 | 금메달의 99%는 금이 아닙니다 | 20초 안에 증명이 안 나올 때 |
| 비교 | 둘 중 하나가 이긴다 | 같은 30평, 한쪽은 3억 더 쌉니다 | 진 쪽을 말하지 않을 때 |
| 마감 | 날짜와 함께 바뀌는 것 | 다음 달부터 청약 규칙이 바뀝니다 | 확인되는 진짜 날짜가 아닐 때 |
| 대상 호명 | 첫 여섯 단어 안에 딱 그 시청자 | 무주택 30대라면 이것부터 보세요 | 「집 있는 분」처럼 너무 넓을 때 |

- 공식 규칙: 첫 문장이 제목의 약속을 확인한다 · 약속은 하나 · 크고 흐릿한 말보다 구체적인 숫자·이름·장면 · 내가 누구인지로 시작하지 않는다.

**시점 규칙** (한국 쇼츠 히트작 12편 + 벤치마크 198편 분석에서 공통으로 확인)

- 그게 무엇인지(정체)는 **처음 10% 안**에 밝힌다.
- 첫 전환어("그런데/하지만/근데 사실")는 **30~35%** 지점.
- **8~12초마다** 다시 붙잡는 문장(질문, "그런데", 짧은 한 방)을 둔다. 구간마다 새 사실 하나 이상(숫자·이름·장면·원리).
- **가장 큰 반전(숫자형이면 가장 큰 숫자)은 55~85%**에 둔다. 제목이 약속한 장면을 너무 일찍 쓰지 않는다.
- 마무리는 짧게(5% 안). 첫 장면을 되받는 비유 · 별칭 · 시청자의 일상 장면으로 돌아오기 · 열린 질문 중 하나. "궁금증이 해결됐길 바라며" 같은 요약형·구독 요청은 쓰지 않는다.

**문장 장치**

1. **수치가 나오면 일상 사물로 환산한다.** 「높이 28미터. 아파트 10층입니다.」
2. **사람을 넣는다.** 기관명보다 행동. 「유찰됐습니다」 ❌ → 「건설사들은 계산기를 두드려 보고 전부 손을 들었습니다」 ⭕
3. **긴 문장 뒤에 짧은 한 방.** 25~30자 뒤에 3~8자. 한 대본에 3번 이상. 한 문장은 30자 안쪽 위주.
4. **백과사전체 금지.** 「~로 알려져 있습니다」 「또한」 「이러한」 「대표적인」 「중요한 역할을 합니다」 「주목받고 있습니다」
5. **현재형, `-니다` 통일.** 「쌓았습니다」보다 「쌓습니다」.
6. **숫자는 읽는 대로 쓰고 물타기하지 않는다.** 「수십 미터」 ❌ → 「수심 30미터」 ⭕. 단, 확인 못 한 숫자는 아예 쓰지 않는다(1-2).
7. **법적 결과를 조건 없이 단정하지 않는다.** 「하자는 전부 내 돈입니다」 ❌ → 「하자 보수 청구가 막힙니다」 ⭕
8. **같은 회사·기관·인물은 대본 안에서 이름 하나로 통일한다.**
9. 특정 채널의 고유 표현(유행어처럼 굳은 문장)을 그대로 쓰지 않는다. 구조만 쓴다.

다 쓴 뒤 **대략 몇 자인지만** 한 줄로 밝힌다. 정확히 셀 필요 없다 — 0-3 표에서 크게 벗어났는지만 본다.

### 1-2 팩트체크 — 대본에 실제로 나온 사실만

먼저 조사하지 않는다. 주제 하나에 사실은 수십 개지만 대본에 남는 건 몇 개뿐이다.

| 사실 | 대본 속 문장 | 출처 | 기준연도 | 맞나 |
|---|---|---|---|---|

- 대본의 **숫자·연도·인명·고유명사·법령 수치·사건 경위·원리 설명·인과 문장**을 확인한다. 숫자가 없는 대본일수록 사건·원리 문장을 빠뜨리지 않는다.
- **서로 다른 출처 두 곳 이상**에서 같은 값이 나와야 ✓. 공식·1차 자료를 먼저 본다(정부·공공기관·국가법령정보센터·통계청·원 논문·당시 신문 원문). 위키·블로그·카페는 단서로만 쓴다.
- 한 곳에서만 본 값은 ⚠️, 못 찾은 값은 **그 문장만 고쳐서** 다시 보여 준다. 대본 전체를 다시 쓰지 않는다.
- 지금 진행 중인 제도·가격은 가장 최신 자료로 보고 기준일을 적는다.
- **반론 한 줄, 주의할 점(caveat) 한 줄.** 그 이상 쓰지 않는다.

### 1-3 자가 검토 — 보여 주기 전에 내가 먼저 고친다

대본과 팩트체크를 쓴 뒤 아래 여덟 시각으로 읽고, 걸린 곳을 고친 **수정본**을 보여 준다. 검토 결과는 표로 함께 낸다(항목 | 판정 | 고친 문장).

근거 표시: **[공식]** 유튜브 공식 문서 · **[연구]** 동료심사 연구 · **[경험칙]** 업계 관행이나 우리 분석의 추정(참고값, 어겨도 실패는 아님). 2026-10-20 조사 기준.

| 시각 | 묻는 것 | 근거 |
|---|---|---|
| **① 넘기는 손가락** | 첫 문장에서 멈추게 하는가 — 유튜브는 「넘기지 않고 본 비율」을 순위 신호로 쓴다. 장면·주제가 바뀌는 자리마다 새 질문이나 떡밥이 하나씩 있는가. 제목이 약속한 답은 늦추되 **반드시 준다**(답을 끝까지 안 주는 미끼형은 만족도 설문에서 손해) | [공식] 첫 몇 초, 순위 신호·설문 / [연구] 호기심 간극, 사건 경계 / [경험칙] 첫 2초, 8~12초 간격 |
| **② 시점** | 정체가 앞쪽에 나오는가. 가장 큰 반전·가장 큰 숫자가 뒤쪽에 있는가. 마지막 문장을 공들였는가(첫 장면을 되받으면 이야기가 닫힌다) | [연구] 정점과 끝을 기억한다 / [경험칙] 정체 10%, 첫 전환 30~35%, 반전 55~85%. 되받는 마무리로 반복 재생을 노리지 않는다 — 수익 기준 조회수는 반복 재생을 세지 않는다 [공식] |
| **③ 숫자** | (숫자가 있을 때) 한 문장에 새 숫자는 1개, 그 옆에 비유 1개(비율·순위·익숙한 물건·단위)인가. 숫자가 세 문장 넘게 연달아 쏟아지지 않는가 | [연구] 비교 문장이 숫자 기억을 높인다, 작업기억 약 4덩어리 |
| **④ 사람** | 사람이나 행동이 한 번 이상 나오는가(기관·물건만 나열하지 않는가) | [연구] 이야기 몰입, 한 사람의 사례 |
| **⑤ 귀로 듣기** | 한 문장에 정보 하나인가. 소리 내어 읽을 때 걸리는 곳 — 읽기 어려운 숫자 표기, 새 정보 없는 연결 문장 | [연구] 긴 문장일수록 이해가 낮다 |
| **⑥ 정확성·분량** | 대본의 사실이 모두 팩트체크 ✓인가. 특정 대회·연도 값에 기준이 붙었는가. 글자 수가 목표 근처인가 — 단, **채우려고 늘리지 않는다** | [공식] 이상적인 길이는 없다, 군더더기·억지로 늘리기 금지 / [경험칙] ±10% |
| **⑦ 양산형 점검** | 최근 대본들과 비교해 질문·핵심 예시와 비유·결론·첫 문장·장면 구성이 다른가(색·글꼴·자막 스타일은 같아도 된다). **채널만의 관점이 한 줄 이상** 있는가(왜 중요한지, 흔한 오해, 직접 해 본 계산·비교). 출처 문장을 읽거나 바꿔 말하기만 하지 않는가. 같은 이야기 틀·같은 콜드 오픈 공식·같은 마무리를 연달아 쓰지 않는가(최근 script.md 머리말의 「콜드 오픈:」으로 확인) | [공식] 양산형 콘텐츠 정책(2025-07, 채널 단위 심사), 재사용 콘텐츠 정책 |
| **⑧ 정책 점검** | 의료: 보건 당국 지침과 반대되는 주장이 없는가, 연구 소개엔 맥락 한 줄. 선거: 공식 출처로만. AI 표시가 필요한가 — 실존 인물 목소리 흉내, 실제 사건·장소의 사실적 재현이 있으면 표시(AI로 쓴 대본·일반 합성 목소리·비사실적 애니메이션은 불필요) | [공식] 의료·선거 허위정보 정책, 합성 콘텐츠 공개 정책 |

- ⑦의 비교 대상: `work/episodes/` 의 최근 `script.md` 몇 편(첫 문장·이야기 틀·마무리만 훑는다).

- 현재형이 원칙이지만, 지난 사건을 말하는 문장은 과거형을 쓴다(「1912년에는 통째로 금이었습니다」).
- 고친 문장에 새 사실이 들어가면 그것도 1-2 방식으로 확인한 뒤 넣는다.

여기서 멈춘다. 사용자가 "계속"이라고 하면 2절로 간다.

## 2. 유형과 이야기 틀

0-2에서 하나 고른다.

| 유형 | 맞는 이야기 틀 |
|---|---|
| 지식·원리 | `how_it_works` 결과 먼저 → 분해 → 조립 → 의미 / `the_catch` 좋아 보임 → 대가 발견 → 재평가 |
| 이야기·사건 | `timeline` 과거 → 전환점 → 현재 → 남은 것 |
| 데이터·숫자 | `one_number` 숫자 → 크기 체감 → 원인 → 대가 / `follow_the_money` 돈이 어디서 와서 어디로 가나 |
| 순위·비교 | `two_things` 같아 보임 → 결정적 차이 → 왜 갈렸나 / `countdown` 하위부터 → 1위 직전 반전 → 1위(55~85%에 공개) → 의미 |
| 꿀팁·방법 | `checklist` 손해 장면(콜드 오픈) → 왜 생기나 → 확인할 것 N개(가장 중요한 것을 뒤쪽에) → 그래도 못 막는 것 한 줄 |
| 퀴즈·테스트 | `quiz` 문제 제시 → 보기 → 생각할 틈(1~2초 무음 표시) → 정답 → 왜 그런가 → 다음 문제 예고 또는 되받기 |

모든 틀이 1-1의 5부 구조와 시점 규칙 위에서 움직인다.

## 3. 제목과 첫 화면 문구 (사용자가 "계속"이라고 한 뒤)

- **제목 3안** — 콜드 오픈과 마무리 떡밥을 담는다. 공식을 강제하지 않고 셋을 비교하게 한다. **번호로 하나를 고르게 한다**(직접 고쳐 적어도 된다). 고른 제목은 script.md 머리말 맨 위 제목과 「## 제목 3안」 아래 「고른 제목:」 줄에 적는다.
- **첫 화면 문구** — 소리 없이 봐도 멈추게 할 한 줄(10자 안팎).

장면 구성은 여기서 정하지 않는다. 화면은 뒤 단계(스타일·렌더)가 대본을 읽고 짠다.

## 4. 저장

확정되면 파일로 저장한다(다음 단계가 읽는다). 폴더: `work/episodes/<영문 짧은 이름>/` (날짜 없이, 예: gold-medal)

- `script.md` — 머리말(제목·주제·유형·틀·길이) + 대본 전문 + 팩트체크 표 + 반론·caveat + 제목 3안 + 첫 화면 문구
- 주제 기록에 폴더를 잇는다: `uv run .claude/skills/shorts-script/scripts/ideas.py pick "<제목>" --episode <폴더 이름>`

## 넘어가기 전 점검 (G1)

- [ ] 주제가 3조건(사실·반론·좁음)을 만족하는가
- [ ] 콜드 오픈이 설명 없이 바로 시작하고, 정체가 10% 안에 나오는가
- [ ] 첫 전환이 30~35%, 가장 큰 반전이 55~85%에 있는가
- [ ] 3부(상승 설명)가 50~70%인가
- [ ] 마지막 문장이 콜드 오픈을 되받는가
- [ ] 대본의 사실이 전부 팩트체크 표의 ✓ 값인가
- [ ] 글자 수가 0-3 표 근처인가
- [ ] 수치가 있으면 일상 비유가 붙었고, 짧은 한 방이 3번 이상인가
- [ ] 백과사전체·조건 없는 법적 단정·물타기 숫자가 없는가
- [ ] 반론·caveat 이 비어 있지 않은가

통과하면 `/shorts-narration` 으로 넘어간다.
